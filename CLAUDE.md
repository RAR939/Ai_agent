# Анализатор учебных чатов

Локальный ИИ-агент с RAG и MCP: читает обезличенные учебные чаты Telegram
(HTML-экспорт с файлами), отвечает на вопросы со ссылками на источники,
находит дедлайны и переносы, прикрепляет к заданиям файлы из чата,
сопоставляет сроки с расписанием. Всё работает локально (Ollama, модель до 8B).

## Главные документы (читай перед работой)
- docs/contracts.md: единый контракт данных (типы, сигнатуры, SQLite, конфиги).
  Это источник правды. Код в src/schemas.py должен совпадать с ним.
- docs/project.md: описание проекта.
- docs/role_1.md ... docs/role_6.md: задачи ролей (пошаговые инструкции).

## Стек
Python 3.11+, pydantic, Ollama (qwen3:8b, bge-m3), Chroma, rank_bm25 + pymorphy3,
SQLite, FastMCP (пакет mcp), Streamlit, pytest.

## Структура репозитория
config/ (config.yaml, disciplines.yaml, roles.yaml шаблон)
data/ (raw, clean, chroma, helper.db: всё в .gitignore)
src/ (schemas.py, config.py, ingest/, index/, tracker/, mcp_server.py, agent.py)
ui/ (app.py, provider.py, tabs/)
eval/, tests/ (fixtures/mini_chat/), docs/, logs/

## Жёсткие правила
1. Контракт неприкосновенен: не добавляй, не переименовывай и не удаляй поля и
   сигнатуры без явной просьбы. Если нужно изменение, остановись и опиши его
   (что было, что стало, кого затрагивает): это pull request с пометкой contract-change.
2. Время только строка ISO 8601 с поясом +03:00. Дата без часа получает 23:59:00.
3. Идентификаторы: сообщение "чат:номер" (elektro:1042), чанк "чат:первый-последний",
   файл "чат:номер:fN". Роли: starosta, teacher, student, unknown.
   Дисциплины: ключи из config/disciplines.yaml латиницей.
4. Нет значения: None, не пустая строка. Ошибки инструментов: {"error": "текст по-русски"}.
5. Настройки (модели, пороги, пути) только из config/config.yaml через load_config().
6. Никаких реальных данных в коде, тестах, логах и коммитах. data/ в .gitignore.
   Для тестов только синтетический чат tests/fixtures/.
7. К каждой функции пиши тест pytest, включая крайние случаи.
8. Работай только в рамках своей задачи, чужие модули не переписывай. Нужна чужая
   функция, которой нет: заглушка с той же сигнатурой и типом результата.
9. Имена на английском, комментарии и сообщения пользователю на русском.
10. Не выдумывай API библиотек. Не уверен в сигнатуре: скажи об этом, проверь
    документацией или быстрым запуском.
11. Новые зависимости добавляй в requirements.txt с зафиксированной версией и
    отдельно сообщай об этом.

## Процесс
- Одна задача: одна ветка feature/<номер>-<кратко>, слияние только через pull request.
- Перед правкой перескажи задачу, файлы и вход/выход по контракту. Код небольшими
  частями, каждая с тестом и командой запуска.
- В конце: чек-лист «как проверить, что готово», честно что не проверено, текст PR.
