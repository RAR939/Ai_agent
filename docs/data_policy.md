# Локальная политика данных — роль 2

## Назначение

- `data/raw/` — экспорт Telegram HTML и исходные вложения; **не коммитить и не пересылать**.
- `data/parsed/` — разобранные сообщения ДО анонимизации; **не коммитить**. Удалить после проверки очищенного набора.
- `roles.local.yaml` — соответствие реальных людей, псевдонимов и меток; **хранить только локально**, не включать в Pull Request.
- `data/clean/` — результат анонимизации с сохранёнными техническими связями; до ручной проверки считать приватным, **не коммитить**.

## Конфигурация ролей

`roles.local.yaml` содержит `people` (локальные `label`, `role`, `category`, `names`) и `authors_by_chat` (для связывания `UNKNOWN_N` предыдущего парсера с меткой в конкретном чате). Разные люди не должны иметь одинаковую метку. Один человек во всех чатах должен иметь одну метку. Категория координаторов сохраняется только локально: поле `Message.role` принимает исключительно `starosta`, `teacher`, `student` или `unknown`.

Алиасы, которые совпадают у разных людей, не заменяются автоматически: они требуют ручного уточнения. Нельзя автоматически считать одним человеком носителей похожих имён, прозвищ или имён, записанных другим алфавитом. Пополнять список только подтверждёнными вариантами.

## Что делает анонимизатор

1. Заменяет `author` на локальную постоянную метку, выставляет разрешённое `role`.
2. Заменяет известные имена и падежные формы в `text` и `attachments[].name` через `pymorphy3`.
3. Маскирует телефоны, адреса почты, ссылки, `@упоминания` и длинные номера.
4. Не меняет `id`, `chat`, `ts`, `reply_to`, `src`, `forwarded`, `attachments[].id`, `msg_id`, `ext`, `size_bytes`, `path`, `bind`.
5. Пишет агрегированную статистику (только численные счётчики) в `data/clean/<chat_id>.report.json`.

**Ограничение:** `attachments[].path` по контракту содержит исходное относительное имя файла. Оно может включать ФИО. Поэтому `data/clean/` нельзя считать безопасным для публикации только на основании выполнения скрипта. Сами вложенные файлы также могут содержать личные данные внутри; не включать их в промпты, репозиторий и рабочие чаты команды.

## Контроль качества

- Выбрать **3 независимые случайные выборки** по 100 сообщений; выборки могут пересекаться между собой, внутри выборки повторов нет.
- Проверить текст, видимые псевдонимы, прямые и косвенные идентификаторы, имена файлов, ссылки и номера. Отдельно просмотреть краткие/двусмысленные ники и падежи фамилий.
- Любую найденную утечку исправить в `roles.local.yaml` или правилах, повторить анонимизацию и взять **новые** выборки. Нельзя объявлять проверку успешной до завершения человеком.
- Отдельно проверять корректность разрешённых ролей и `+03:00` в финальном JSONL.
- После одобрения удалить сырые JSONL из `data/parsed/`; HTML и исходные файлы оставить только в защищённой локальной папке согласно правилам команды.

## Настройки

Для пути к данным используется `paths.data` из `config/config.yaml` через проектный `load_config()`; локальный справочник передаётся явным параметром `--roles`. Парсер и анонимизатор не изменяют контракты из `schemas.py`.
