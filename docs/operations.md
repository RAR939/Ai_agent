# Эксплуатация

Для того, кто ведёт сервер и данные. Установка сервера: `docs/server_setup.md`, настройки: `docs/configuration.md`.

## Жизненный цикл данных
1. **Экспорт и обезличивание** (роль 2, локально): HTML-экспорт Telegram с вложениями → сообщения формата `Message` без реальных имён,
   телефонов и ссылок. Парсер и обезличивание **ещё не написаны** (`docs/known_issues.md`).
2. **На сервер** кладут только обезличенное: `data/clean/<чат>.jsonl`; файлы вложений: `data/raw/<чат>/files/` (путь в сообщении
   относительно `data/raw/<чат>/`). Сырой экспорт и `config/roles.local.yaml` на сервер не нужны.
3. **Индекс:** `python -m src.index.build --chat <чат>` (нужна Ollama с `bge-m3`) или кнопка «Обновить индекс».
4. **Дедлайны:** `python -m src.tracker.pipeline --chat <чат>` (нужна Ollama с `qwen3`) или «Обработать новые сообщения».
   Новые сообщения появились: повторите шаги 2 (дописать файл) и 4; уже обработанные не затрагиваются.
5. **Расписание:** вкладка «Расписание» или `python -m src.tracker.schedule_import файл.xlsx --dry-run` (предпросмотр), без `--dry-run` запись.
   Шаблон Excel: `docs/schedule_template.xlsx`. Новое расписание заменяет прежнее.
6. **Подтверждения:** очередь в интерфейсе (✅ и ❌) разбирает любой участник; порог сомнения `tracker.confidence_threshold`.

После смены параметров чанкинга или модели эмбеддингов (`retrieval.*`, `models.embed`) индекс нужно построить заново.

## Обновление программы
```bash
cd /opt/helper && git pull && source .venv/bin/activate && pip install -r requirements.txt
python scripts/check_env.py && sudo systemctl restart helper-ui
```
Схема базы создаётся при первом обращении (`CREATE TABLE IF NOT EXISTS`), существующие данные не стираются. Если в версии менялся формат индекса,
в заметках к PR об этом сказано: тогда `python -m src.index.build --chat <чат>`.

## Резервные копии
| Что | Как | Если потеряли |
|---|---|---|
| `data/helper.db` (дедлайны, история, очередь, расписание, метки) | `sqlite3 data/helper.db ".backup 'копия.db'"` или копия файла при остановленной службе | история переносов и подтверждения теряются, дедлайны можно восстановить повторной обработкой |
| `data/clean/`, `data/raw/` | копия папок | восстановить из экспорта у роли 2 |
| `config/config.local.yaml`, `config/roles.local.yaml`, `/etc/helper.env` | копия | настроить заново |
| `data/chroma/`, `data/index_chunks.jsonl`, `data/bm25.pkl` | не нужна | пересобирается индексацией |
| `eval/gold_deadlines.jsonl`, `data/labels/` | в git (метки) и копия таблиц | размечать заново |

## Журналы (`logs/`)
| Файл | Что пишет |
|---|---|
| `agent_trace.jsonl` | по строке на вопрос агента: время, вопрос, трасса вызовов инструментов (`ToolCall`), ответ, секунды, модель, `prompt_version` |
| `extract_calls.jsonl` | каждый разбор сообщения моделью: идентификатор, версия промпта, модель, ответ |
| `extract_failures.jsonl` | сообщения, где модель дважды вернула негодный JSON |
Журналы вне git и содержат тексты вопросов и ответов: храните с теми же правами, что и данные. Ответ модели и решение человека хранятся отдельно
(таблица `labels`: `model_json` и `human_json`), чтобы сравнивать (задел под статью).

## Оценка качества
- Трекер на синтетике: `python -m eval.tracker_eval --write` (обновляет `docs/tracker_eval.md`).
- Эталонная разметка Q1: `python -m eval.gold ...` (`docs/annotation_guide.md`).
- Агент: вопросы в `eval/gold_agent.jsonl`, но скрипта прогона пока нет (`python -m eval.evaluate` пуст).
- Поиск: таблица экспериментов `docs/retrieval_experiments.md` ждёт реальных чатов и эталона.
Метрики на реальных чатах появятся только после разметки.

## Напоминания о дедлайнах
`python -m src.tracker.reminders --hours 24` шлёт уведомления **рабочего стола** (`plyer`): на сервере без графической сессии они не
видны, запускайте у себя на ноутбуке или в планировщике на машине с экраном.

## Разбор неполадок
Сначала `python scripts/check_env.py`: он называет, чего не хватает.

| Симптом | Причина и что делать |
|---|---|
| Интерфейс показывает «Лабораторная №4», «Теорию вероятностей» | режим макета: в `config/config.local.yaml` поставить `ui.use_mock: false` и перезапустить |
| «Не удалось получить ответ: ...» в чате | Ollama недоступна (служба, адрес, токен) или модель не скачана: `ollama pull` на сервере |
| Дедлайны не появляются после «Обработать новые» | нет `data/clean/<чат>.jsonl`; Ollama недоступна (сообщения остаются необработанными); смотрите `logs/extract_failures.jsonl` |
| Поиск всегда «В материалах этого нет» | индекс не построен; `retrieval.min_score` слишком высок для вашей модели реранкера; нет реранкера и данных |
| Первый поиск очень долгий | загружается реранкер (и скачивается из Hugging Face один раз); на CPU это медленно: GPU или `retrieval.use_reranker: false` |
| «Файл не найден» в карточке | файла нет в `data/raw/<чат>/files/` (не выгружен при экспорте или не скопирован) |
| Расписание не записывается | в предпросмотре есть ошибки (например, не найдена дисциплина по алиасам из `disciplines.yaml`); исправьте файл или алиасы |
| Срок «на следующей паре» не превратился в дату | не загружено расписание этой дисциплины |
| Агент «зациклился» или не вызывает инструменты | модель слабая для вызова инструментов: `agent.mode: rules` (запасной режим) или модель крупнее |
| Две «Обработки» подряд не дали новых результатов | так и должно быть: уже обработанные сообщения повторно не разбираются |
| Страница отвалилась | закрылся SSH-туннель: откройте заново |
