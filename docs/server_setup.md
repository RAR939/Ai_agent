# Модель на сервере

Схема: приложение (интерфейс, трекер, база, индекс, агент) работает на ноутбуке, а **Ollama с моделями на сервере с GPU**.
К серверу ходят три вещи: ответы и вызов инструментов (`qwen3`), разбор сообщений трекером и эмбеддинги для поиска (`bge-m3`).
Всё идёт через один клиент `src/llm.py`; адрес и токен берутся из `config/config.yaml` и окружения.

```
ноутбук: Streamlit + агент + трекер + индекс (Chroma, BM25, реранкер)
        │  http://localhost:11434  (SSH-туннель)
        ▼
сервер с GPU: Ollama (qwen3, bge-m3)
```

## 1. Сервер (один раз)
1. Установите Ollama по инструкции на официальном сайте и убедитесь, что она видит GPU (`ollama ps` после первого запроса).
2. Оставьте её слушать только локальный адрес (по умолчанию `127.0.0.1:11434`). **Не открывайте порт 11434 в интернет**: у Ollama нет авторизации.
3. Скачайте модели: `ollama pull qwen3:8b` (при GPU можно взять крупнее, выбор фиксируется замером, задача 0.5) и `ollama pull bge-m3`.
4. Чтобы модель не выгружалась между запросами и запросы нескольких человек шли параллельно, задайте для службы переменные
   `OLLAMA_KEEP_ALIVE` (например `24h`) и `OLLAMA_NUM_PARALLEL`. Имена и значения сверьте с документацией Ollama вашей версии.
5. Закрытый ключ каждого участника не делится: у каждого свой SSH-ключ, добавленный на сервер.

## 2. Доступ с ноутбука: SSH-туннель (рекомендуется)
Простейший и безопасный вариант для небольшой команды: шифрование, вход по ключу, наружу открыт только SSH.
```bash
ssh -N -L 11434:localhost:11434 пользователь@адрес-сервера
```
Пока туннель открыт, для приложения Ollama «локальная»: в `config.yaml` ничего менять не нужно (`models.host` пусто).
Если порт 11434 на ноутбуке занят своей Ollama, пробросьте на другой и задайте адрес только себе:
```bash
ssh -N -L 21434:localhost:11434 пользователь@адрес-сервера
export OLLAMA_HOST=http://localhost:21434          # Windows PowerShell: $env:OLLAMA_HOST = "http://localhost:21434"
```
Переменная окружения **важнее** `models.host`. Если команда в одной сети или на VPN, можно прописать общий адрес в `models.host`
(например `http://llm.vpn:11434`), но тогда порт доступен всей сети.

### Через интернет (только если нельзя иначе)
Нужен HTTPS-прокси (nginx, Caddy) перед Ollama, который пропускает запросы только с заголовком `Authorization: Bearer <токен>`.
Приложение отправит его само, если задана переменная `OLLAMA_API_KEY` (токен **не** кладётся в конфиг и в git):
```bash
export OLLAMA_HOST=https://llm.example.org
export OLLAMA_API_KEY=...
```
Настройку прокси проверьте по документации выбранного сервера: здесь она не проверялась.

## 3. Проверка
`python scripts/check_env.py` показывает адрес, наличие токена, время ответа и какие модели скачаны на сервере
(`ollama pull ...` выполняется на сервере). Медленный отклик (больше 1,5 с на простой запрос) помечается предупреждением:
каждый вопрос агента делает несколько обращений к модели.

## 4. Что остаётся на ноутбуке
- **Реранкер** (`BAAI/bge-reranker-v2-m3`, библиотека `sentence-transformers`, нужен `torch`) считается **на ноутбуке** и
  скачивается из Hugging Face один раз. Без GPU он медленный. Если мешает, отключите `retrieval.use_reranker: false`
  (тогда порог `min_score` не применяется, ответ «в материалах этого нет» даёт только пустая выдача поиска).
  Вынос реранкера на сервер отдельной задачей не сделан.
- Chroma, BM25, SQLite с дедлайнами и файлы чатов (`data/`) остаются у каждого локально. Индекс и база не общие:
  у каждого участника своя копия данных.
- Файлы вложений на сервер **не отправляются** (их содержимое проект не анализирует).

## 5. Данные и согласие участников (до загрузки реальных чатов)
Сервер арендованный, то есть сообщения обрабатывает третья сторона. В `docs/project.md` сказано, что проект локальный
(«всё работает на ноутбуке», облачные модели вне границ, согласие получено на использование сообщений). Перед отправкой
реальных чатов нужно решить и записать:
1. Покрывает ли полученное согласие участников обработку на арендованном сервере. Если нет, получить отдельное.
2. Условия провайдера: не хранит ли и не использует ли запросы для обучения, где физически находится сервер.
3. Отправляются только **обезличенные** сообщения (`data/clean`), реальные имена и сырой экспорт (`data/raw`) на сервер не попадают.
4. Обновить `docs/project.md` (разделы 1, 8, 11) и текст отчёта: проект больше не «полностью локальный».
5. Журналы сервера не должны сохранять тексты запросов (проверить настройки логирования).
До этого на сервер можно слать только синтетический мини-чат.
