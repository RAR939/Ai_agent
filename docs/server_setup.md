# Запуск на сервере

Сервер ваш и удалённый. Рекомендуемая схема: **всё тяжёлое работает на сервере, на ноутбуках нужен только браузер**
(и SSH-доступ). Если нужно, можно держать приложение на ноутбуках, а на сервере только Ollama (раздел 6).

```
ноутбук: браузер ── SSH-туннель ──►  сервер (GPU):  Streamlit-интерфейс, агент и MCP-сервер, трекер,
                                                    индекс (Chroma, BM25, реранкер), SQLite, файлы чатов, Ollama (qwen3, bge-m3)
```

Что считается на сервере: ответы и вызов инструментов (`qwen3`), разбор сообщений трекером, эмбеддинги (`bge-m3`),
**реранкер** (`sentence-transformers`, сам берёт GPU), индексация, база дедлайнов, загруженные файлы и расписание.
Все участники видят **общую** базу, индекс и расписание.

## 1. Подготовка сервера (один раз)
1. **Ollama.** Установите по инструкции с официального сайта; убедитесь, что она видит GPU (`ollama ps` после первого запроса).
   Пусть слушает только локальный адрес (по умолчанию `127.0.0.1:11434`). Порт 11434 наружу не открывайте: у Ollama нет авторизации.
   Скачайте модели: `ollama pull qwen3:8b` (при GPU можно крупнее, выбор фиксируется замером, задача 0.5) и `ollama pull bge-m3`.
   Чтобы модель не выгружалась между запросами и запросы шли параллельно, задайте службе Ollama `OLLAMA_KEEP_ALIVE` (например `24h`)
   и `OLLAMA_NUM_PARALLEL`; имена и значения сверьте с документацией вашей версии Ollama.
2. **Приложение.** Python 3.11+, `git clone`, затем
   ```bash
   cd /opt/helper && python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt            # torch с CUDA: ставьте сборку под ваш драйвер (pytorch.org)
   ```
3. **Локальные настройки** (файл не в git, значения накладываются на `config.yaml`): `config/config.local.yaml`
   ```yaml
   ui:
     use_mock: false        # настоящие данные вместо макета
   ```
   Ollama на этом же сервере, поэтому `models.host` пусто. Остальное (модель, пороги, пути) можно менять там же без правки `config.yaml`.
4. **Проверка:** `python scripts/check_env.py` (Ollama, модели, GPU для реранкера, данные, индекс).
5. **Данные.** Обезличенные чаты положите в `data/clean/<чат>.jsonl` (вложения: `data/raw/<чат>/files/`), например
   `scp elektro.jsonl сервер:/opt/helper/data/clean/`. Папка `data/` вне git. Затем индекс и дедлайны:
   `python -m src.index.build --chat elektro` и `python -m src.tracker.pipeline --chat elektro` (или кнопки во вкладке «Источники»).

## 2. Запуск
Вручную: `streamlit run ui/app.py` (настройки в `.streamlit/config.toml`: слушает **только** `127.0.0.1:8501`).
Как служба: шаблон `deploy/helper-ui.service` (поправьте пользователя и путь):
```bash
sudo cp deploy/helper-ui.service /etc/systemd/system/ && sudo systemctl daemon-reload && sudo systemctl enable --now helper-ui
```
Шаблон служб не проверялся на настоящем сервере.

## 3. Доступ с ноутбука: SSH-туннель (рекомендуется)
У каждого участника свой SSH-ключ на сервере; наружу открыт только SSH:
```bash
ssh -N -L 8501:localhost:8501 пользователь@адрес-сервера
```
Потом в браузере `http://localhost:8501`. Если команда на VPN, можно запустить с адресом VPN
(`streamlit run ui/app.py --server.address <адрес VPN>`), но тогда **включите пароль** (раздел 4).

## 4. Защита
- **Пароль на вход (необязательно):** переменная окружения `HELPER_UI_PASSWORD` (для службы в `/etc/helper.env`, права 600).
  Если задана, интерфейс сначала просит пароль. Это защита от случайных посетителей в сети, а не замена SSH и VPN.
  Не выставляйте Streamlit в интернет без HTTPS-прокси.
- **Токен Ollama** нужен только если Ollama доступна не локально (раздел 6): `OLLAMA_API_KEY` в окружении.
- Сырой экспорт (`data/raw`) и реальные имена (`config/roles.local.yaml`) на сервере тоже вне git; права на папки только у пользователя службы.

## 5. Несколько пользователей и обновление
- Интерфейс открыт у нескольких человек сразу: у каждого свой сеанс, данные общие. Долгие операции («Обновить индекс»,
  «Обработать новые») над одним чатом выполняются по очереди, повторная обработка ничего не меняет.
- Поиск держит реранкер и индекс в памяти процесса: первый запрос после запуска медленнее, дальше быстро.
- Обновление: `git pull && pip install -r requirements.txt && sudo systemctl restart helper-ui`.
  Структура индекса может измениться между версиями: после обновления `python -m src.index.build --chat <чат>`.

## 6. Вариант: приложение на ноутбуках, на сервере только Ollama
Всё идёт через `src/llm.py`. Туннель к Ollama: `ssh -N -L 11434:localhost:11434 пользователь@сервер`, тогда `models.host`
оставляем пустым. Если порт занят своей Ollama, пробросьте на другой и задайте только себе
`export OLLAMA_HOST=http://localhost:21434` (переменная важнее `models.host`). Общий адрес команды (VPN) можно записать
в `models.host`. Через интернет (если иначе нельзя) нужен HTTPS-прокси с проверкой заголовка `Authorization: Bearer <токен>`;
токен приложение берёт из `OLLAMA_API_KEY`, настройку прокси проверьте по документации вашего прокси (здесь не проверялась).
В этом варианте реранкер (`torch`) и Chroma работают **на каждом ноутбуке** (реранкер можно отключить: `retrieval.use_reranker: false`),
а база и индекс не общие.

## 7. Данные и согласие участников
Сервер ваш, поэтому данные не уходят третьим лицам, и проект остаётся без облачных сервисов. Но он перестаёт быть «только на ноутбуке»:
- обезличенные чаты лежат на удалённой машине: ограничьте доступ (SSH-ключи, права, шифрование диска, кто имеет доступ к серверу);
- на сервер кладите только обезличенные данные (`data/clean`); сырой экспорт и реальные имена остаются у роли 2 локально;
- в `docs/project.md` (разделы 1, 5, 8, 11) и отчёте поправьте формулировки «всё работает на ноутбуке»;
- если серверу пользуется кто-то, кроме команды, участники чатов должны знать об этом (согласие).
