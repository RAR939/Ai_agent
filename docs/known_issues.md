## 3. Технические ограничения
- **Поиск.** Лексический BM25 на очень маленьком наборе чанков (единицы) возвращает пусто из-за отрицательных весов; на реальном корпусе не проявляется.
  Без реранкера порог `min_score` не применяется, честный отказ даёт только пустая выдача. Кэш `get_discussion` не сбрасывается после переиндексации.
  Роль автора в тексте чанка записана заглавными (`STAROSTA`), в контракте строчными. Окно чанка не режется по суткам, но режется по `max_chunk_chars`.
- **Агент.** Инструмент `process_new_messages` ждёт завершения обработки, а `agent.timeout_sec` (120 с) может быть короче долгой обработки.
  Качество выбора инструментов на `qwen3:8b` не измерено, `agent_v2` против `agent_v1` не сравнивали.
- **Трекер.** Напоминания шлют уведомления рабочего стола (`plyer`), на сервере бесполезны. Два известных ограничения разбора дат помечены `xfail` в `tests/test_dates.py`
  (`docs/tracker_notes.md`). Чат в мини-чате совпадает с дисциплиной, в реальных чатах дисциплины будут вперемешку.
- **Интерфейс.** Очередь подтверждений общая для всех. Мобильная раскладка новой карточки задания не проверялась людьми.
- **Данные.** Индекс и база у каждого свои, если приложение запущено на ноутбуках; общие только при запуске на сервере.

## 4. Не проверено
- Работа на настоящем сервере с GPU: Ollama, `torch` с CUDA, служба systemd, `OLLAMA_KEEP_ALIVE` и `OLLAMA_NUM_PARALLEL` (имена сверить с документацией вашей версии Ollama), HTTPS-прокси с токеном.
- Настоящая модель: выбор инструментов, качество ответов и разбора, время ответа; индексация и поиск с настоящими Chroma и реранкером.
- Реальные чаты (их не было), порог 80% согласованности на живых разметчиках, удобство интерфейса на человеке не из команды.
- Python 3.11 (тесты запускались на 3.13) и результат GitHub Actions на последних PR.
