# Руководство по разметке дедлайнов

Версия `guide_v1`. Нужно для эталонного набора (30–50 сообщений), по которому считаются точность и полнота трекера,
доля верных дат и файлов. Все примеры вымышленные (из синтетического мини-чата).

**Главное правило:** размечайте только то, что **написано в сообщении** (и в сообщении, на которое оно отвечает).
Ответ модели вам не показывают и смотреть его нельзя. Не уверены: ставьте метку и пишите причину в `comment`.

## Как заполнять таблицу

Каждому разметчику выдаётся `data/labels/sheet_<номер>.csv` (Excel или Google Таблицы, кодировка UTF-8).
Серые колонки читайте (`ts`, `author_role`, `reply_to_text`, `text`, `files`), колонки меток заполняйте.
Для сообщения без срока заполняется **только `has_deadline = нет`**. Проверка: `python -m eval.gold validate <таблица>`.

| Поле | Что писать |
|---|---|
| `has_deadline` | `да` или `нет` |
| `discipline` | ключ из `config/disciplines.yaml`: `elektro`, `models`, `algo` |
| `kind` | `lab`, `hw`, `midterm`, `exam`, `other` |
| `task` | как назвал автор: `Лаб.2`, `ДЗ 1`, `Курсовая работа этап 1` |
| `due_text` | срок **дословно**: `до пятницы`, `на 30.10`, `12 ноября в 10:00` |
| `due_at` | дата `23.10.2026` или `2026-10-23`, с временем `12.11.2026 10:00`; без времени ставится 23:59 |
| `action` | `new`, `move`, `cancel` |
| `fuzzy` | `да` или `нет` |
| `files_gold` | id файлов через `;`: `elektro:1010:f1; elektro:1041:f1` |
| `comment` | что угодно, на метки не влияет |

## has_deadline: есть ли срок

Срок есть, если сообщение **называет, когда сдать конкретное задание** (даже размыто), переносит его или отменяет.

| Да | Нет |
|---|---|
| «Лаб.2 по электротехнике сдаём до пятницы» | «кто уже сдал Лаб.1? хочу сравнить время» (сдавать не просят) |
| «ДЗ 1 по электротехнике отменяется» (отмена тоже дедлайн-событие) | «до сих пор не понимаю, зачем нам эти деревья» («до» это предлог) |
| «ДЗ 4 по алгоритмам надо сдать на днях» (срок есть, но размытый) | «дату сообщу позже» (даты нет и не названа) |

Трудные случаи:
- **Ответ на вопрос.** «когда сдавать ДЗ 1?» → «до среды»: срок есть **у ответа** (`ДЗ 1`, до среды); вопрос срока не содержит.
- **«Кто-нибудь сделал ДЗ?»** без срока: нет.
- **Неуверенность автора** («кажется, Лаб.8 до воскресенья»): ставим `да`, в `comment` пишем «неуверенно».
- **Напоминание** о том же сроке («напоминаю: Лаб.1 до 9 ноября»): `да`, `action = new`.
- **Пересланное сообщение** со сроком: `да`, как обычное.
- **Шум** (эмодзи, «ахах», «спасибо») и вопросы без срока: нет.

## action: новый, перенос или отмена

| Значение | Когда | Пример |
|---|---|---|
| `new` | срок задан впервые (или напоминание) | «Лаб.3 по электротехнике до 6.11» |
| `move` | срок **меняется** | «Лаб.2 перенесли на 30.10», «Лаб.2 теперь до 30.10 включительно» |
| `cancel` | задание отменено | «ДЗ 3 по алгоритмам отменяется, вместо него будет контрольная» |

Нельзя: ставить `move` только потому, что в сообщении есть «до»; перенос без указания, какого задания, всё равно `move`
(пишем в `task` то, что видно из контекста).

## task, kind, discipline

- `task`: название как у автора; если в сообщении названия нет (ответ «до 5 ноября»), берите его из сообщения, на которое ответили
  (`reply_to_text`) или из соседних. Нет ниоткуда: пишите `Задание` и поясните в `comment`.
- `kind`: «Лаб.», «ЛР» → `lab`; «ДЗ», «домашка» → `hw`; «рубежка», «контрольная», «РК» → `midterm`; «экзамен», «зачёт» → `exam`; остальное (курсовая) → `other`.
- `discipline`: по тексту («по электротехнике») или по контексту чата. Не определить: спросите тимлида, не угадывайте.

## due_text, due_at, fuzzy

- `due_text` копируется из сообщения без правок. Для `cancel` пусто.
- `due_at` считаете **вы** от даты сообщения (`ts`): «до пятницы» в среду это ближайшая пятница. Дата без времени получает 23:59.
  Если время названо («12 ноября в 10:00»), оно сохраняется.
- «На следующей паре по электротехнике»: дата и время **начала** этого занятия по расписанию.
- **Размытый** срок («на днях», «скоро», «в ближайшее время»): `fuzzy = да`, `due_at` пусто.
  Для `cancel` дата пуста и `fuzzy = нет`. Для остальных действий нужно одно из двух: либо дата, либо `fuzzy = да` (иначе проверка вернёт ошибку).

| Сообщение (дата `ts`) | `due_text` | `due_at` | `fuzzy` |
|---|---|---|---|
| «до пятницы» (вт 20.10) | до пятницы | 23.10.2026 | нет |
| «послезавтра» (ср 28.10) | послезавтра | 30.10.2026 | нет |
| «ДЗ 4 надо сдать на днях» | на днях | (пусто) | да |

## files_gold: какие файлы относятся к заданию

Файл относится к заданию, если его **прислали**:
1. в том же сообщении, что и срок;
2. **тот же автор** в пределах нескольких минут (в проекте 10) после объявления, в том числе файл без подписи;
3. в **ответ** на объявление или в сообщении, **на которое ответили** объявлением.

Не относятся: файл другого автора в то же время (например, чужой отчёт «для примера»), файл через час, файлы к другим заданиям.
При переносе перечисляются **все** файлы задания после переноса (прежний и новый). Файл не выгружен при экспорте: его нет, не пишем.
В колонке `files` видны id в формате `<чат>:<номер>:f<n>`.

## Порядок работы

1. Подбор сообщений (тимлид): `python -m eval.gold sample --chat <чат>`, это примерно 20 со сроком, 10 с переносом или отменой и 10 трудных без срока.
2. Раздача: `python -m eval.gold assign --annotators 6`. Каждый размечает свои 10–15 сообщений, **20% набора (8) размечают двое независимо**.
3. Сборка: `python -m eval.gold build sheet_1.csv --out data/labels/gold_1.jsonl` (по одному файлу на разметчика).
4. Согласованность на двойных: `python -m eval.gold agreement gold_1.jsonl gold_2.jsonl`.
   Нужно **не меньше 80%** совпавших решений целиком; смотрим и каппу Коэна по наличию срока и действию.
5. Разбор расхождений: `python -m eval.gold diff gold_1.jsonl gold_2.jsonl`, обсуждаем, дополняем это руководство.
6. Итог: `python -m eval.gold merge gold_1.jsonl gold_2.jsonl --resolved решения.jsonl --out eval/gold_deadlines.jsonl`.

Таблицы с текстами сообщений остаются в `data/labels/` (не в git). В репозиторий попадает только `eval/gold_deadlines.jsonl`: метки без текстов.
Запись в нём формата `LabelRecord`: `msg_id`, `human_json` (поля выше плюс `due_at_gold`, `files_gold`), `prompt_version = guide_v1`, `model_name = human`.
