# Как работать с репозиторием

## Быстрый старт
```
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pytest
```
Перед работой прочитайте `CLAUDE.md` и `docs/contracts.md` (источник правды по данным).

## Ветки
- `main` защищена: прямые коммиты запрещены, слияние только через pull request (PR) с одним одобрением.
- Одна задача: одна ветка `feature/<номер задачи>-<коротко>`, например `feature/2.4-html-parser`.
- Исправления: `fix/<коротко>`. Ветку держим короткой и актуальной (подтягиваем `main`).
- Коммит: одна законченная мысль, понятное сообщение по-русски или по-английски.

## Зависимые ветки
Каждый PR открываем **в `main`**. Если одна ветка зависит от другой, либо делаем один общий PR, либо сначала сливаем нижний, а потом у верхнего меняем базу на `main`.
Не сливайте PR в чужую ветку-основу: в `main` попадёт только нижний слой, остальное затеряется (так было со стопкой интеграции).

## Данные
В репозиторий не попадают: `data/`, базы, индексы, `.env`, реальные сообщения и файлы чатов.
Для тестов только синтетические данные из `tests/fixtures/`. Заметил утечку: сразу сообщи команде.

## Шаблон описания PR
```
## Что сделано
## Как запустить и проверить
(точные команды, ожидаемый результат)
## Какие тесты добавлены
## Затронутые контракты
(ожидаемый ответ: никакие; иначе см. «contract-change»)
## Не проверено
```

## Ревью
Ревьюит другой человек из команды, не автор. Ревьюер запускает `pytest`, сверяет типы с
`src/schemas.py`, проверяет, что нет реальных данных и что настройки взяты из конфига.

## Определение «готово»
1. Код слит в `main` через PR.
2. `pytest` проходит локально и в GitHub Actions.
3. В README модуля написано, как запустить.
4. Ревьюер подтвердил.

## Правило contract-change
Контракт (`src/schemas.py`, `docs/contracts.md`, сигнатуры, схема SQLite) меняется только отдельным PR
с меткой `contract-change`. В описании: что было, что стало, кого затрагивает. Обновляем вместе
схемы, документ, заглушки и тесты, пишем в общий чат. Принимает роль 1 после одобрения затронутых ролей.
Добавлять поля «для себя» без такого PR нельзя.
